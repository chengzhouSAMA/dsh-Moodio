## 坐标系

V-A 是情感计算里的二维连续模型，不是离散标签：

- `valence` ∈ [-1, 1]，负=消极/压抑，正=积极/明亮。
- `arousal` ∈ [-1, 1]，负=平静/低沉，正=亢奋/紧张。
- `intensity` = 到原点的距离，越大越"情绪浓"。

## 四个维度：情绪方向、激活、攻击性、规模感

只用 V-A 两维会犯两个已经踩过的错：

> 1. **"低沉"被当成"悲伤"，"快"被当成"欢快"** —— 二维只有 4 个象限。
> 2. **《英雄主义》被判"悲伤"，实际是"悲壮"** —— 它有 34.6dB 动态、
>    40.9% 时间满响、对比度 27.8，是实测最宏大的一首；但它**没有失真、
>    没有高频噪声**，所以只做"攻击性"一维时会把它误读成"安静"。

关键结论：**"力量"有两种，必须分开度量**

| 维度 | 取值 | 衡量什么 | 谁高 |
|---|---|---|---|
| `valence` | −1..1 | 情绪正负 | — |
| `arousal` | −1..1 | 激活/快慢 | — |
| `texture` | 0..1 | **攻击性**：失真、打击、噪声 | 摇滚/电子/金属 |
| `grandeur` | 0..1 | **规模感**：动态落差、持续强奏、厚织体 | 管弦/史诗 |

它们可任意组合：

| 组合 | 说法 | 例 |
|---|---|---|
| 负 + 低激活 + 低攻击 + **高规模** | **悲壮** | 英雄主义（texture 0.10 / grandeur 0.72） |
| 负 + 低激活 + 低攻击 + 中低规模 | **悲伤** | 诀别书（0.15 / 0.51） |
| 正 + 低激活 + 低攻击 + 高规模 | **壮丽** | Victory（0.33 / 0.69） |
| 正 + 低激活 + 中攻击 + 中规模 | **平静** | Yellow（0.36 / 0.55） |
| 正 + 高激活 + **高攻击** + 中规模 | **热烈** | Runaway Baby（0.57 / 0.48） |
| 效价≈0 + **高攻击** | **强烈** | Die For You（0.53 / 0.45） |

分档：`texture` low<0.40 / high≥0.45；`grandeur` mid≥0.45 / high≥0.65。

决策顺序是**先规模、后攻击性**：同为小调低沉，grandeur 高是"史诗的悲壮"，
grandeur 低是"私人的悲伤"；texture 只决定"是否带躁动"。

## 该读哪个字段

输出里四层同时存在、互不矛盾：

| 字段 | 含义 | 何时用 |
|---|---|---|
| `emotion_4d.emotion` | **四轴词**（悲壮/悲伤/壮丽/昂扬/热烈/强烈…） | **默认用这个** |
| `emotion.emotion` | 二维词（只有悲伤/欢快/平静/紧张/平淡…） | 与旧结果对比时 |
| `emotion.label` | 四象限 id | 程序做稳定四分类 |
| `texture` / `grandeur` | 两个连续维度及分量 | 需要解释"为什么"时 |

`emotion_4d.directional=False` 表示效价接近 0，模型**拒绝判断方向**，
此时只描述气质（平缓/平实/强烈/宏伟/辽阔/尖利/素淡），
不要把它转述成"某首歌很欢快"。

`emotion_4d.texture_parts` / `.grandeur_parts` 给出各分量归一值，
用来说"为什么判成高宏大"，例如 `full_loud_share=0.52` 表示"有一半时间在满响"。

## 强度与证据

`intensity` 分档：`flat` < `mild` < `moderate` < `strong`。
`magnitude` 是 V-A 平面上的模长（0~1.41）。

`modes.acoustic.arousal` / `.valence` 给出贡献最大的 3 个特征。
`segments[].evidence` 给出该段所有归一化后的特征值（0~1）。

## 两套标定模式，含义不同

这是最容易误读的地方，先确认你拿到的是哪一种：

| 模式 | 0 点含义 | 能拿来比什么 |
|---|---|---|
| `fixed`（默认） | 所有特征处于区间中点的不动点 | 跨曲库可比；反映绝对倾向 |
| `corpus-relative` | 本曲库的中位数 | 只能在同一批结果内部比较 |

`fixed` 模式下，一个整体偏明亮、大调为主的流行曲库会得到普遍为正的 valence——
那是**如实反映**，不是 bug。换成 `corpus-relative` 会把 0 点挪到该库中间，
四象限都用得上，但同一首歌换库后符号可能翻转，不能跨库比较。

## 必须知道的局限

1. **没有人工标注。** 权重来自文献中的方向性结论，不是拟合人类评分。
   同一批音乐里比较"谁更激昂"是可靠的；说"这首歌的 arousal 是人类平均 7.2/9"是不可靠的。
2. **这是"听感线索"，不是"听者感受"。** 它反映音频的客观属性（速度、调式、能量、和声），
   不反映特定听众的联想、记忆与文化背景。
3. **歌词与语义不参与。** 一首歌词悲伤但伴奏轻快的歌会被判为轻快。
4. **`confidence` 衡量输入质量，不衡量预测准确率。** 高置信度只说明"特征提取可靠"。
5. **中性点曾有过一次严重错误。** 早期 `VALENCE_NEUTRAL` 误设为 0.47（应为可验算的 0.25），
   导致全库判"低沉"，四象限只剩两个可用。修复后由 `tests/validate_calibration.py`
   的"中性不变量"用例强制保证。如果你在旧结果里看到大量 melancholic，那是旧版本的产物。

## 证据字段怎么用

`modes.acoustic.arousal` / `.valence` 给出贡献最大的 3 个特征。
`segments[].evidence` 给出该段所有归一化后的特征值（0~1）。

看到 `normalized` 里某项恰好是 0.000 或 1.000，说明该特征已饱和，
对应通道的区分能力在该音轨上失效——这点必须如实告诉用户，不要假装没看见。
